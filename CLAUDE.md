## 1. Stack (fixed)
- Unity 6 LTS (6000.0.x), C#, URP (mobile renderer), IL2CPP, ARM64.
- Netcode for GameObjects 2.x + Unity Transport (UDP). Server-authoritative DEDICATED SERVER (headless Linux + Windows builds). No Unity Relay, no Photon (extra hop = extra latency; we must control server placement on the 5G SA edge).
- New Input System (EnhancedTouch) for gestures.
- TextMeshPro for UI. No other third-party paid deps.
- Target: Android (min API 26, target latest). Keep code platform-agnostic so iOS is a build-target switch (Android-only parts isolated behind `INetworkInfoProvider`).

## 2. Game concept
Title: MOTTAINAI (Japanese "what a waste!" — use as title-screen tagline). English UI. Kids-friendly, cartoon, eco theme. Inspired by "Fart Together" (co-op raft steered by synchronized players through a hazard course) — coordination is the fun.
- A team of 3 on one inflatable raft on a polluted river/lake.
- LEFT PADDLER and RIGHT PADDLER: each paddles one side. Left stroke = forward thrust + yaw right; right stroke = forward thrust + yaw left; both in sync (within 0.25 s) = straight "sync boost" (+30% thrust, small splash VFX, "SYNC!" popup).
- COLLECTOR: throws a net at waste. Must aim; misses waste time.
- Goal: collect max waste in 2:00 without hitting obstacles. MVP: 1 obstacle hit = GAME OVER (confirmed; `hitsToGameOver = 1`, keep HP system in code for later modes).
- Shield power-up: touch it → immune to obstacles for 6 s (bubble VFX, blinking last 1.5 s).

## 3. Controls (no virtual joystick, no buttons in gameplay)
Landscape only. Camera: third-person behind/above raft (~35° pitch), smooth follow.
- Paddlers: swipe DOWN anywhere = stroke forward; swipe UP = back-paddle (brake + reverse yaw). Stroke power = clamp(swipe speed) → 0.4..1.0. Stroke cooldown 0.18 s. Haptic tick on stroke.
- Collector: TAP a waste item in 3D (raycast) → net flies to it (travel 0.25 s, range 7 m, cooldown 0.6 s). Swipe in a direction also throws toward that direction (fallback for small targets). Generous hit radius (1.2× collider) for kids.
- Role shown with a big icon at screen top; first 3 s of match show a one-line gesture hint.

## 4. Tuning (my design values — put ALL in one `GameTuning` ScriptableObject + JSON override downloaded from server)
- River width 24 m, raft 2.4 m wide. River current drift 2.5 m/s forward.
- Stroke impulse: +1.6 m/s forward, ±28°/s yaw kick decaying (damping 3/s). Max speed 7 m/s. Water drag 0.6.
- Course: procedural from server seed, 40 m chunks, ~650 m for 2:00.
- Obstacles: start 1 per 25 m, ramp linearly to 1 per 12 m at 1:45. Guarantee a free lane ≥ 3× raft width in every chunk (validate at generation).
- Obstacle types: Rock, Big Rock, Iceberg, Moored Old Boat (wreck), Floating Log, Shark (patrols laterally 2 m/s, 6 m amplitude, fin telegraph 1.5 s before entering lane).
- Waste: clusters of 3–5 every ~7 m, bobbing; 30% placed near obstacles (risk/reward).
- Shield: 1 per ~150 m, never in first 20 s.
- Mix & score (penalties for toxic applied at END, shown as separate line on results):
  | Type | Color (bin standard) | Examples (models/icons) | Weight | Score |
  |---|---|---|---|---|
  | Plastic | Yellow #F2C200 | bottle, bag, straw cup | 30% | +10 |
  | Paper/Cardboard | Blue #1E6FD9 | box, carton | 15% | +10 |
  | Glass | Green #2E9E44 | bottle, jar | 15% | +15 |
  | Organic | Brown #7A4A21 | banana peel, apple core | 12% | +5 |
  | Metal | Grey #8C959F | can, tin | 13% | +20 |
  | Valuable | Gold #FFC83D (sparkle) | treasure chest, ring | 3% | +100 |
  | Toxic/Hazardous | Red #D62828 + hazard symbol | barrel, battery, oil drum | 12% | −30 (at end) |
- Combo: 3 non-toxic catches within 3 s → x1.5 for the next catch. Score popups per catch with type color.
- End screen: total, per-type counts with colors, toxic penalty, accuracy %, distance, "Ocean cleaned: X kg" fun stat, plus network stats summary (see §6).

## 5. Networking architecture (THE differentiator: low latency + high data volume over 5G SA)
- One server process = authoritative sim at 60 Hz tick (`NetworkConfig.TickRate = 60`). Clients send input every tick (unreliable sequenced), events (net throw, stroke) as reliable RPC with client timestamp.
- Server simulates raft physics, spawns course, validates catches with lag compensation: rewind waste positions by measured one-way latency (RTT/2, capped 150 ms) before hit test.
- Clients: interpolation buffer adaptive = max(1 tick, jitter p95) — expect ~17–33 ms on 5G SA. Local immediate feedback for own gestures (paddle anim, net throw VFX), corrected by server.
- HIGH DATA VOLUME, by design (all of it gameplay-meaningful, not padding):
  1. Full-state snapshots at 60 Hz of ALL floating entities in a 60 m window (raft, ~150–300 waste/obstacles with bobbing pose, shark, water flow field samples) — custom compact serializer (quantized pos/rot), no NetworkTransform per object (too slow/heavy); one `WorldSnapshot` message per tick via `CustomMessagingManager`, unreliable fragmented.
  2. Login = "DLC" download: client fetches a Content Pack from server HTTP (C# `HttpListener` inside the server build, port 8080): tuning JSON + skin/texture pack (Kenney textures + generated high-res water normal maps, target 20–40 MB) → shown with live MB/s progress bar. Cached by hash; "Force re-download" button for the demo.
  3. Live telemetry stream to server (device RTT, FPS, network type) and server-side session log.
- Ports: UDP 7777 (game), TCP 8080 (HTTP login/content/telemetry).
- Login: username only → server returns session token + room list. Rooms with 4-letter code. Lobby: create/join by code, pick role (Left/Right/Collector), ready → start. Server fills missing roles with BOTS (simple AI) so 1 or 2 phones can still demo.
- Always online: no offline mode. Even solo test connects to a server (localhost server build in Editor via "Host Server in Editor" toggle for dev only).
- Disconnect handling: role taken over by bot within 1 s; rejoin by same token restores role.

## 6. 5G SA showcase (must be visible to judges)
- Android plugin (Java/Kotlin AAR or `AndroidJavaObject` calls) behind `INetworkInfoProvider`:
  - Detect network: `TelephonyManager.getDataNetworkType() == NETWORK_TYPE_NR` → "5G SA"; LTE with `TelephonyDisplayInfo` override `NR_NSA`/`NR_ADVANCED` → "5G NSA"; else LTE/Wi-Fi. Permission READ_PHONE_STATE (graceful if denied → "Unknown").
  - On Android 13+ request a network with `NET_CAPABILITY_PRIORITIZE_LATENCY` (5G network slicing / URSP); if granted, bind the process to it; show "Latency slice: ON/OFF/unsupported".
- Net HUD overlay (toggle with 3-finger tap, ON by default in demo build): network type badge, RTT avg / p95 / jitter (ms), server tick, snapshot rate, downlink & uplink kbps, packets/s, packet loss %, FPS.
- "Network Lab" screen from main menu: 10 s ping burst (UDP echo 100 Hz) + throughput test (download 20 MB from server) → result card. Save each run to CSV on device + server (`/logs/session_*.csv`) for the pitch graphs (Wi-Fi vs 4G vs 5G NSA vs 5G SA).
- Server deploy: the dedicated server runs on THIS local machine (the demo laptop). Detect the OS and build/run the matching server target. On startup the server prints all its IPv4 addresses + ports in big text (console and a small server status window/log) so phones can type it in. Write `DEPLOY.md` (one page): cmd line, ports, firewall rules for this OS (open UDP 7777 / TCP 8080), and how phones on the 5G SA network reach the laptop (laptop must be on the same 5G SA network, e.g. via the hackathon's 5G CPE/router; warn that a carrier CGNAT blocks inbound).

## 7. Performance
- 60 FPS target on mid-range Android, never below 30. `Application.targetFrameRate = 60`, VSync off, URP mobile: no realtime shadows (blob shadow decals), MSAA 2x max, render scale auto-drop to 0.8 if FPS < 45 for 3 s.
- Object pooling for all spawned entities, no per-frame allocations in hot paths, GPU instancing for waste/obstacle materials.
- Simple water: custom URP unlit HLSL shader with vertex sine waves + scrolling normal; tinted dirty-green near waste clusters.
